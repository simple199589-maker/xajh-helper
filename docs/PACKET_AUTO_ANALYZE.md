# 封包自动分析解包 — 使用说明

> 维护：开发工作台「封包」页 + `packet/auto_analyze`  
> 目标：一次配置 x32dbg 后，日常只看**功能响应**和**日志**，即可定位明文 / 密文 / 核心钩子，无需反复调试。

---

## 图例（先看这个）

| 标记 | 含义 | 谁做 |
|------|------|------|
| **【需你】** | 必须你本人介入的操作（本机 UI / 游戏 / 调试器） | 你 |
| **【一次】** | 只需做一次（或换客户端版本后再做） | 你 |
| **【可选】** | 非必须；没有也能走主路径 | 你（可跳过） |
| **【自动】** | 工具 / 脚本 / 分析器完成，无需手算 | 工具 |
| **【只看】** | 你只需阅读结果，不要改配置 | 你（观察） |

**原则：** 标了 **【需你】** 的步骤不完成，后面分析一定空或废；其余尽量交给工具。

## 0. 谁做什么（总览）

### 必须你介入的（【需你】清单）

| # | 动作 | 频率 | 说明 |
|---|------|------|------|
| 1 | 启动游戏并进角色 | 每次会话 | 要有活进程才能挂调试器 |
| 2 | 管理员打开 x32dbg，附加 `xajh` | 每次调试会话 | 工具不能替你附加进程 |
| 3 | 加载脚本 + 填断点日志文本 | **【一次】** | x32dbg 2020 常无法全自动写 Log text |
| 4 | 游戏内触发功能（开箱等） | 每次采样 | 产生真实 PLAIN/SEND10 |
| 5 | 保存 / 导出调试日志 | 每次采样 | 把 log 落到磁盘 |
| 6 | 点「分析日志」或跑 CLI | 每次采样 | 触发分析（1 次点击即可） |
| 7 | 看游戏功能是否成功 | 每次采样 | 业务真伪只能人眼确认 |

### 工具自动完成的（【自动】清单）

| 动作 | 说明 |
|------|------|
| 生成 x32dbg 脚本与配置清单 | 面板「生成 x32dbg 脚本」 |
| 解析 `PLAIN` / `SEND10` / `UPD_*` | `packet/auto_analyze` |
| 明文 ↔ 密文配对 | lookback 窗口对齐 |
| 已知壳识别与字段试释 | `crypto_knowledge.KNOWN_SHELLS` |
| 写报告 / CORE_POINTS / JSON | `.issues/packets/auto_analyze_*` |
| 搜最新日志路径 | 「分析最新」 |

### 你不必再做的

- 每次重找明文缓冲区地址  
- 手对 RC4 逆推单包密文  
- 手工数日志行做 SEND10↔PLAIN 对齐  
- 反复改断点「猜」核心点（地址已固化在知识库）

## 2. 核心概念（【只看】背景知识）

> 本节全部为阅读用，**无需操作**。分析器会按这些规则自动标结果。

### 2.1 管道（当前 build，映像基址 `0x00400000`）

```text
marshal 明文 Octets
  → GNET::ARCFourSecurity::Update (0x00DAFAF0)   // 入口 = 出站明文
  → 缓冲就地变密文
  → send_wrapper (0x00D0C130)
  → ws2_32.send                                  // 出口 = 密文
```

### 2.2 日志标签

| 标签 | 含义 | 典型用途 |
|------|------|----------|
| `PLAIN` | Update 入口 dump | **出站明文**（入站时此处是密文） |
| `SEND10` | `ws2_32.send` 且 `len==10` | 网络**密文**锚点（开箱类） |
| `UPD_OUT` | Update 返回后同一缓冲 | 出站密文 / 入站明文（S2C 关键） |
| `SETKEY` | SetKey / KSA | 会话密钥初始化（低频） |
| `UPD_IN` | 与 PLAIN 同义 | 脚本/旧日志兼容 |

**重要：** 同明文、不同密文 = RC4 流正常，**不要**从单包密文反推字段。字段看 `PLAIN`。

### 2.3 已知明文壳（【自动】识别）

| hex 前缀 | 名称 | 说明 |
|----------|------|------|
| `22080721000100000000` | `open_chest_c2s10` | 开箱/采集类 10B C2S 壳（同图冻结） |
| `22` | `gamedata_type22` | GNET type=0x22（Gamedata 类）前缀 |

开箱壳字段试释（分析结论里会自动打印）：

| 偏移 | hex | 说明 |
|------|-----|------|
| 0 | `22` | type 34，疑 GamedataSend |
| 1–4 | `08 07 21 00` | 子命令/常量（同图未变） |
| 5–8 | `01 00 00 00` | LE int32 = 1 |
| 9 | `00` | pad |

> 同图多样本下 10B 壳可不带实体 id；目标多半由交互上下文决定。

机器可读核心点：面板「打开 CORE_POINTS」或 `.issues/packets/CORE_POINTS.md`（分析时【自动】刷新）。

## 3. GUI 使用（推荐）

### 3.1 入口

| 步骤 | 标记 | 你做什么 |
|------|------|----------|
| 1 | **【需你】** | 启动游戏并进入角色 |
| 2 | **【需你】** | 仓库根目录运行 `python main.py` |
| 3 | **【需你】** | 拖到游戏窗口取句柄 → 进开发工作台 |
| 4 | **【需你】** | 打开 **「封包」** 页 |

### 3.2 页面分区（【只看】）

| 区域 | 作用 | 你是否必须点 |
|------|------|----------------|
| **核心点** | 明文/密文钩子速览 | 否；需要时点「复制/打开」 |
| **自动分析解包** | 日志 → 结论 | **是**（分析时点一次按钮） |
| **封包捕获 (pktmon)** | 动作窗密文差分 | **【可选】** |

### 3.3 一次配置 x32dbg（【一次】+【需你】）

> 整节通常只做 **一遍**。换客户端版本或地址失效后再做。

| 步骤 | 标记 | 动作 | 说明 |
|------|------|------|------|
| 1 | **【需你】**（点一下） | 面板 **「生成 x32dbg 脚本」** | 文件由工具【自动】写出 |
| — | **【自动】** | 写出 `build/generated/x32dbg_auto_plain_cipher.txt`、`.issues/packets/X32DBG_ONCE_SETUP.md` | 无需手写脚本 |
| 2 | **【需你】** | **管理员**运行 x32dbg，附加正在玩的 `xajh.exe`，F9 | 无法自动化 |
| 3 | **【需你】** | Script → 加载 `build/generated/x32dbg_auto_plain_cipher.txt` | 选文件加载 |
| 4 | **【需你】** | 脚本第一行点一下，按 **Space** 执行到 `ret` | 下好断点 |
| 5 | **【需你】【一次】** | **断点**页填日志文本（下表） | x32dbg 2020 限制，必须人手勾选/粘贴 |
| 6 | **【可选】** | 禁用嘈杂旧断点（如裸 `DB0CC2`） | 减干扰 |
| 7 | **【可选】** | 仅明文时用 `build/generated/x32dbg_auto_plain_only.txt` | 主路径不必须 |

**【需你】【一次】** 断点日志表（粘贴到 x32dbg 断点编辑框）：

| 断点 | 暂停条件 | 日志文本 | 快速恢复 | 不输出日志 |
|------|----------|----------|----------|------------|
| `0x00DAFAF0` | （空，或点射时再收紧） | `PLAIN {mem;16@[[esp+4]+4]}` | **勾** | **不要勾** |
| `ws2_32.send` | `[esp+0xC]==0xA` | `SEND10 {mem;10@[esp+8]}` | **勾** | **不要勾** |
| `0x00DAFB74`（可选） | （空） | `UPD_OUT {mem;24@[[esp+4]+4]}` | **勾** | **不要勾** |

> 这一步是整个链路里**最关键、且工具替代不了**的人工操作。配错则永远没有可用日志。

### 3.4 日常分析（配置完成后的循环）

| 步骤 | 标记 | 动作 |
|------|------|------|
| 1 | **【需你】** | F9 游戏跑着，**触发目标功能** 1～3 次（如开箱） |
| 2 | **【只看】** | 日志窗口是否出现 `PLAIN` / `SEND10` 行（没有 → 回 §3.3） |
| 3 | **【需你】** | **保存日志**到 `.issues/packets/x32dbg_runtime.log`（或任意路径） |
| 4 | **【需你】**（点一下） | 面板 **「分析日志」** 或 **「分析最新」**（可选先「选择…」指定文件） |
| 5 | **【自动】** | 解析、配对、壳识别、写报告 |
| 6 | **【只看】** | 列表里的 `[摘要]` / `[结论]` / `C:密文 ← P:明文` |
| 7 | **【只看】【可选】** | 「打开报告」→ `auto_analyze_latest.md` |
| 8 | **【需你】【只看】** | **确认游戏内功能是否真的成功**（与包是否对应） |

列表标记含义（【自动】标注）：

- `[F]` = 命中冻结开箱壳  
- `[S]` = 命中其它已知壳  
- `[ ]` = 未识别壳  

### 3.5 pktmon 差分（【可选】密文侧）

> 整节可选。没有 x32dbg 时粗筛「动作前后多出来的包」；**字段级仍以 PLAIN 为准**。

| 步骤 | 标记 | 动作 |
|------|------|------|
| 1 | **【需你】** | 取句柄保证 PID 正确 |
| 2 | **【需你】** | 选动作：`open_chest` / `pickup` / … |
| 3 | **【需你】** | **开始捕获** → baseline **站桩别乱动** → 游戏内操作 → **结束** |
| 4 | **【自动】** | pktmon 转储 + 差分写出 `captures/tcp/` |
| 5 | **【只看】【可选】** | 点「捕获目录」查看 |

python -m packet.auto_analyze log1.txt log2.txt

## 7. 如何读分析结果（【只看】）

> 分析按钮点完后，**只读不改**。

优先顺序：

1. **事件计数** — 有没有 `PLAIN`、有没有 `SEND10`  
2. **配对表** — 每个 `SEND10` 对齐到哪条 `PLAIN`  
3. **主明文壳** — 是否命中 `open_chest_c2s10` 等  
4. **字段说明** — 壳内偏移试释  
5. **核心链路** — 明文 @ Update，密文 @ send  
6. **（回到游戏）** — **【需你】** 功能是否真成功  

示例摘要：

```text
PLAIN/UPD_IN=482 SEND10=2 配对=2/2 已知壳=2 | x32dbg_runtime.log
```

## 8. 排障

| 现象 | 更可能是谁的问题 | 处理（标记） |
|------|------------------|--------------|
| 无 PLAIN、无 SEND10 | **【需你】** 断点/日志未配好 | 回 §3.3；快速恢复要勾，「不输出日志」不要勾 |
| 有 SEND10 无 PLAIN | **【需你】** 漏了 Update 断点 | 补 `0x00DAFAF0` + PLAIN 日志文本 |
| 有 PLAIN 无 SEND10 | **【需你】** 动作不是 10B 或条件过严 | 放宽 send 条件，或只靠 PLAIN |
| 配对为空 | 采样时机 / 日志不完整 | **【需你】** 点射：开 BP→操作→关 BP→存 log |
| 日志刷屏卡顿 | Update 过热 | **【需你】** 点射或只开 SEND10 |
| 地址对不上 | 换版 | **【需你】** 更新 `crypto_knowledge`（或让 agent 改） |
| 分析失败「日志不存在」 | **【需你】** 路径 | 「选择…」或拷到 `.issues/packets/` |
| 报告字段像错的 | 先 **【只看】** 游戏是否成功 | 功能失败时的包不要当正样本 |

保存日志细节：`.issues/packets/HOW_TO_SAVE_LOG.md`（其中步骤均为 **【需你】**）。

## 9. 安全与范围

- 仅限**本地授权**客户端分析与竞赛/研究环境。  
- 不重放线上密文、不做未授权协议滥用。  
- 明文截取在本地调试器断点完成（**【需你】** 挂调）。
